# 第七章：测试数据填充 — seed.py

开发时需要一个有数据的数据库才能调试。`seed.py` 一键创建管理员和示例帖子。它只有 38 行，但"幂等"这个设计点值得单独讲一章。

```python
from database import Base, SessionLocal, engine
from models import Topic, User
from auth import hash_password


def seed():
    Base.metadata.create_all(bind=engine)
    db = SessionLocal()

    try:
        admin = db.query(User).filter_by(username="admin").first()
        if not admin:
            admin = User(username="admin", password_hash=hash_password("admin123"), is_admin=True)
            db.add(admin)
            db.flush()

        existing = db.query(Topic).first()
        if not existing:
            topic = Topic(
                title="欢迎来到论坛",
                content="这是论坛的第一个帖子。欢迎加入社区讨论！\n\n## 论坛规则\n\n- 请保持友善和尊重\n- 支持 Markdown 格式\n- 点击左上角 **发帖** 开始新话题",
                author_id=admin.id,
            )
            db.add(topic)
            db.commit()
            print("Seed data inserted: admin user + 1 topic")
        else:
            db.commit()
            print("Seed data already exists, skipping")
    except Exception:
        db.rollback()
        raise
    finally:
        db.close()


if __name__ == "__main__":
    seed()
```

## 创建了什么

只有两样东西：

1. **一个管理员账号** —— `admin` / `admin123`，`is_admin=True`
2. **一篇欢迎帖** —— 标题"欢迎来到论坛"，作者是上面那位管理员

刻意**不**批量造用户、帖子和评论。原因很简单：seed 的职责是让新环境"能登录、首页不是空的"，而不是模拟一个热闹社区。数据多了反而会干扰开发时观察真实的前端渲染效果。

## 幂等性

多次运行结果一致：

```
第一次 → Seed data inserted: admin user + 1 topic
第二次 → Seed data already exists, skipping
```

两个检查保证幂等：

- **`if not admin`** —— 按用户名查 `admin`，存在就跳过创建
- **`if not existing`** —— 用 `db.query(Topic).first()` 判断"库里有没有任何帖子"，有就跳过

**为什么幂等这么重要？** 因为 `seed.py` 会被反复执行——本地每次重建数据库要跑、部署脚本 `deploy.sh` 每次上线也会跑（见第九章）。如果不做幂等检查，反复执行会产生一堆重复的 admin 账号，或者报唯一约束冲突直接中断部署。**能被安全地重复执行，是脚本类工具的基本素养。**

## db.flush() 与 db.commit()

| 方法 | 写入数据库？ | 事务提交？ | 能拿自增 id？ |
|------|:--------:|:--------:|:-----------:|
| `add()` | 否（缓存） | 否 | 否 |
| `flush()` | 是（发 SQL） | 否（可回滚） | **是** |
| `commit()` | 是 | 是 | 是 |

用 `flush` 只是为了拿到 admin 的 id 给帖子用——`topic = Topic(..., author_id=admin.id)` 需要 `admin.id`。但此时**还没有 commit**，admin 和 topic 仍在同一个事务里。

注意代码里一个微妙的结构：`db.commit()` 只出现在两个分支内部，而不是在流程末尾统一调用：

- 建贴分支：`add(topic)` → `commit()`（这一次 commit 把 admin 和 topic 一起提交）
- 跳过分支：仍然调了一次 `db.commit()`——因为可能刚刚 `db.add(admin)` 过（admin 是新建的、但帖子已经存在），需要把 admin 落库

这正是"幂等"之外的第二层考虑：**两个检查互相独立**，可能"有帖子但没有 admin"这种奇怪状态（手工删过用户之类），代码要能分别处理。

## 异常处理：回滚 + 保留原始错误

```python
try:
    ...
except Exception:
    db.rollback()
    raise
finally:
    db.close()
```

- **`rollback()`** — 出错时丢弃所有未提交的改动，避免留下半截数据
- **`raise`（裸 raise）** — 回滚之后**重新抛出原异常**。如果不写这句，异常会被吞掉，脚本"看起来成功了"、实际上什么都没写。裸 `raise` 保留原始 traceback，方便定位
- **`finally: db.close()`** — 无论成功失败都归还连接


## 本章要点

- `seed.py` 只创建一个管理员和一篇欢迎帖，保持"最小可用"
- 幂等靠"先查后建"：`if not admin` 与 `if not existing`，可反复安全执行
- `flush()` 只发出 SQL 不提交，用于提前拿到自增 id，让 admin 和 topic 留在同一事务
- `try / except / finally`：出错回滚并 `raise` 重新抛出，最后 `close()` 连接
- 默认密码 `admin123` 仅供开发，上线后必须修改
