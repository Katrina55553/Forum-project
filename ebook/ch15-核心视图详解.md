# 第十五章：核心视图详解

本章讲三个"内容视图"：帖子列表、帖子详情、发帖/编辑。它们构成论坛的主干。社交类视图（消息、聊天）放在第十七章。

## 帖子列表 — HomeView.vue

### 四种状态

HomeView 要同时应对"加载中、出错、空、有数据"四种局面：

```javascript
const topics = ref([]);
const total = ref(0);
const pages = ref(0);
const page = ref(1);
const loading = ref(true);
const error = ref("");

async function fetchTopics() {
  loading.value = true;
  error.value = "";
  try {
    const res = await getTopics(page.value, size, q.value, currentTag.value);
    topics.value = res.data.items;
    total.value = res.data.total;
    pages.value = res.data.pages;
  } catch {
    error.value = "加载失败，请稍后重试";
  } finally {
    loading.value = false;
  }
}
```

命名上有个小陷阱：接口返回的字段是 `total`，而组件里用 `total` 和 `pages` 两个 ref 分别存总数和总页数。

### 模板渲染（四种状态分支）

```html
<!-- 1. 加载中：骨架屏 -->
<div v-if="loading" class="skeleton-list">
  <div v-for="n in 5" :key="n" class="skeleton-row">
    <div class="skeleton-line w-70"></div>
    <div class="skeleton-line w-40"></div>
  </div>
</div>

<!-- 2. 错误：提示 + 重试 -->
<div v-else-if="error" class="state error">
  <p>{{ error }}</p>
  <button class="btn-retry" @click="fetchTopics">重试</button>
</div>

<!-- 3. 空数据 -->
<div v-else-if="topics.length === 0" class="state empty">
  <div class="empty-mark">✦</div>
  <p>这里还很安静，写下第一篇吧。</p>
  <router-link to="/topic/new" class="btn-cta">发布新帖</router-link>
</div>

<!-- 4. 正常渲染 -->
<div v-else class="topic-list">...</div>
```

### 骨架屏动画

加载态不是转圈，而是一组会"呼吸"的灰色线条，用纯 CSS 实现：

```css
.skeleton-line {
  height: 14px;
  background: linear-gradient(90deg,
    var(--color-border-light) 0%, var(--color-border) 50%, var(--color-border-light) 100%);
  background-size: 200% 100%;
  border-radius: 4px;
  animation: shimmer 1.6s infinite linear;
}
@keyframes shimmer {
  0%   { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

做法是给一条渐变背景一个 200% 的宽度，再移动它的 `background-position`，看起来就像光在扫过。

### 搜索与标签筛选：状态同步到 URL

搜索框提交时不是直接把值存进 ref，而是**更新 URL 的 query**，让 URL 成为筛选状态的唯一来源：

```javascript
const q = computed(() => route.query.q || "");
const currentTag = computed(() => route.query.tag || "");

function doSearch() {
  const val = searchInput.value.trim();
  page.value = 1;
  const query = {};
  if (val) query.q = val;
  if (currentTag.value) query.tag = currentTag.value;   // 搜索时保留标签
  router.push({ name: "home", query });
}

function filterByTag(slug) {
  page.value = 1;
  const query = { ...route.query };
  if (slug === currentTag.value) {
    delete query.tag;                                   // 再点一次取消筛选
  } else {
    query.tag = slug;
  }
  router.push({ name: "home", query });
}
```

标签筛选栏直接复用了列表接口返回的结构：顶部 `tags` 数组由 `getTags()` 单独拉取，每个标签带 `slug`（用于 query）和 `name`（用于显示）：

```html
<div v-if="tags.length" class="tags-bar">
  <button v-for="tag in tags" :key="tag.id"
          class="tag-chip" :class="{ active: currentTag === tag.slug }"
          @click="filterByTag(tag.slug)">
    <span class="tag-hash">#</span>{{ tag.name }}
    <span class="tag-count">{{ tag.count }}</span>
  </button>
</div>
```

### 一个避免"双重请求竞态"的 watcher

页面加载和翻页都靠 `watch(page, fetchTopics)` 触发请求。问题是 URL 的 query 变化时，既想重置到第一页、又想刷新列表，如果两个都做就会**发两次请求、且顺序不可控**。代码用一个 watcher 巧妙地串起来：

```javascript
onMounted(() => {
  fetchTopics();
  fetchTags();
});
watch(page, fetchTopics);
// query 变化时只重置 page，由 page watcher 触发 fetchTopics，避免双重请求竞态
watch(() => route.query, () => {
  if (page.value !== 1) {
    page.value = 1;      // 改了 page → 触发上面的 watcher 去请求
  } else {
    fetchTopics();       // page 本来就是 1 → 直接请求
  }
}, { deep: true });
```

逻辑是：**如果 page 需要变，就只改 page（让 `watch(page)` 去请求）；如果 page 不用变，才自己请求。** 两种情况下请求都只发一次。

## 帖子详情 — TopicDetailView.vue

### Markdown 渲染与 XSS 防护

详情页要把 Markdown 渲染成 HTML，渲染结果通过 `v-html` 注入。**凡是 `v-html`，都必须先消毒**，否则用户可以在帖子里写 `<script>` 或 `<img onerror>` 搞 XSS：

```javascript
import { marked } from "marked";
import DOMPurify from "dompurify";
import hljs from "highlight.js/lib/core";              // core + 按需注册语言
import javascript from "highlight.js/lib/languages/javascript";
import python from "highlight.js/lib/languages/python";
// ……共注册 23 种常用语言（bash/json/yaml/xml/css/markdown/sql/java/c/cpp/
// csharp/go/rust/php/ruby/diff/dockerfile/ini/kotlin/swift 等），完整清单见源码
import "highlight.js/styles/github-dark.css";

hljs.registerLanguage("javascript", javascript);
hljs.registerLanguage("python", python);
// ……其余语言同样逐个 registerLanguage

// marked v5+ 移除了 setOptions({highlight})，改用自定义 renderer 接管代码块渲染
marked.use({
  renderer: {
    code({ text, lang }) {
      const language = lang && hljs.getLanguage(lang) ? lang : null;
      const highlighted = language
        ? hljs.highlight(text, { language }).value
        : hljs.highlightAuto(text).value;      // 没指定语言时在已注册语言里自动猜测
      const cls = language ? `hljs language-${language}` : "hljs";
      return `<pre><code class="${cls}">${highlighted}</code></pre>\n`;
    },
  },
});

const renderedContent = computed(() => {
  if (!topic.value?.content) return "";
  return DOMPurify.sanitize(marked(topic.value.content));   // 渲染后再消毒
});
```

```html
<div class="content" v-html="renderedContent"></div>
```

注意顺序：`marked()` 先把 Markdown 转成 HTML，`DOMPurify.sanitize()` 再过滤掉危险标签/属性。少了第二步，Markdown 里嵌入的恶意 HTML 会原样执行。

> **为什么不是 `marked.setOptions({ highlight })`？** 那是 `marked` v4 及更早的写法，**v5 起已被移除**（改由独立的 `marked-highlight` 插件承担），本项目装的是 `marked@15`——旧写法会被**静默忽略**，代码不报错、控制台不警告，只是渲染出来的 `<pre><code>` 里没有任何高亮标记。改用自定义 `renderer.code` 的好处是顺手把 `class` 也定了：`hljs` 是主题样式（`github-dark.css`）的选择器，`language-*` 则是给编辑器/复制按钮之类做二次识别用的。
>
> 这里还有个安全细节值得留意：**`hljs` 的输出是已经做过 HTML 转义的**，所以即使代码块里写 ```` ```html ```` 包着 `<script>alert(1)</script>`，渲染出来也是转义后的文本而非可执行标签——我们实测确认过这一点。当然它后面仍会过一遍 `DOMPurify`，两层都不省。
>
> 另一个容易忽略的点在 import 那一行：为什么不能写 `import hljs from "highlight.js"`？因为那是**全量入口**，会把 highlight.js 内置的约 190 种语言定义全部打进这个 chunk——本项目的 `TopicDetailView` chunk 一度因此达到 **980 kB（gzip 316 kB）**，是主包（166 kB）的近 6 倍，`vite build` 会报超 500 kB 警告。改成 `highlight.js/lib/core` + 只 `registerLanguage()` 需要的 23 种语言后，chunk 降到 **124 kB（gzip 40 kB）**。**凡是"库很大但只用一小部分"的场景，都先查查它有没有 core/按需入口。** 顺带一提：`github-dark.css` 主题是硬编码的，在默认"暖纸"亮色主题下代码块也是深色——这是个有意的样式取舍，知道就好。

### 点赞：状态来自服务端，不是本地猜

旧版教程写的是本地 `isLiked` ref + 乐观更新。**当前实现不同**：是否已点赞由后端返回的 `is_liked` 决定，点赞/取消后直接用响应里的最新 `likes_count` 覆盖：

```javascript
function isLiked() {
  return topic.value?.is_liked || false;
}

async function handleLike() {
  if (!auth.user) {
    router.push("/login");     // 未登录先请去登录，不硬发请求
    return;
  }
  likeLoading.value = true;
  try {
    if (isLiked()) {
      const res = await unlikeTopic(topic.value.id);
      topic.value.likes_count = res.data.likes_count;
      topic.value.is_liked = false;
    } else {
      const res = await likeTopic(topic.value.id);
      topic.value.likes_count = res.data.likes_count;
      topic.value.is_liked = true;
    }
  } catch {
    // ignore duplicate（重复点赞后端会拒绝，静默处理即可）
  } finally {
    likeLoading.value = false;
  }
}
```

这样设计的好处是**多端一致**：如果能在别处点赞，回来刷新拿到的 `is_liked` 一定是权威的。代价是点击后要等一次网络往返，所以用一个 `likeLoading` 防止连点。

### 评论渲染

顶层评论交给递归组件 `CommentItem`，只负责把当前登录用户作为 `auth` 传下去，并监听它抛上来的两个事件：

```html
<CommentItem
  v-for="c in topic.comments"
  :key="c.id"
  :comment="c"
  :auth="auth.user"
  @reply-created="handleReplyCreated"
  @comment-deleted="handleCommentDeleted"
/>
```

`CommentItem` 内部不直接调用创建评论的接口（这一点旧教程写错了），它只负责"收集内容 + 冒泡事件"，真正的请求由详情页统一发起：

```javascript
async function handleComment(parentId = null, content = null) {
  const text = content || commentText.value;
  if (!text.trim()) return;
  await createComment(topic.value.id, text, parentId);   // 顶层评论 parentId=null
  if (!parentId) commentText.value = "";                 // 只清空顶层输入框
  await fetchTopic();                                    // 重新拉取整棵评论树
}
function handleReplyCreated({ parentId, content }) {
  handleComment(parentId, content);
}
```

这个设计把"网络请求"集中在父组件、把"局部 UI 状态"留在子组件，职责更清晰。评论系统细节见第十七章。

## 发帖/编辑 — TopicEditView.vue

同一个组件既是"发帖"也是"编辑"，靠路由参数区分：

```javascript
const isEdit = computed(() => !!route.params.id);
```

### 初始化：先拿热门标签，编辑时再补数据

```javascript
async function init() {
  // 无论发帖还是编辑，都要先拿热门标签喂给 TagInput
  try {
    const tagsRes = await getTags();
    allTags.value = tagsRes.data;
  } catch { /* ignore */ }

  if (isEdit.value) {
    pageLoading.value = true;
    try {
      const res = await getTopicForEdit(route.params.id);
      title.value = res.data.title;
      content.value = res.data.content;
      tags.value = res.data.tags?.map(t => t.name) || [];   // 后端给对象，前端用名字
    } catch {
      error.value = "加载失败";
    } finally {
      pageLoading.value = false;
    }
  }
}
```

编辑走的是**专门的 `getTopicForEdit(id)`** 接口（对应 `/topics/{id}/edit`），而不是详情接口，后者不会带可编辑字段。

### 标签：交给 TagInput

```html
<div class="field">
  <label>标签</label>
  <TagInput v-model="tags" :suggestions="allTags" />
</div>
```

`v-model` 把 `tags`（字符串数组）和组件双向绑定，`suggestions` 传入热门标签供点选。

### 提交

```javascript
async function handleSubmit() {
  if (!title.value.trim()) {
    error.value = "标题不能为空";
    return;
  }
  loading.value = true;
  try {
    const data = { title: title.value.trim(), content: content.value, tags: tags.value };
    if (isEdit.value) {
      const res = await updateTopic(route.params.id, data);
      router.push(`/topic/${res.data.id}`);
      showToast.success("更新成功");
    } else {
      const res = await createTopic(data);
      router.push(`/topic/${res.data.id}`);
      showToast.success("发帖成功");
    }
  } catch (e) {
    error.value = e.response?.data?.detail || "操作失败";
  } finally {
    loading.value = false;
  }
}
```

两种模式共用一个表单，只是提交时调不同的接口（`updateTopic` / `createTopic`），成功后都跳到帖子详情。

## 本章要点

- HomeView 用四种状态分支（加载/错误/空/数据）覆盖所有局面，骨架屏是纯 CSS 动画
- 搜索与标签筛选都同步进 URL 的 query；`watch` 通过"只改 page 或直接请求"避免双重请求
- 详情页的 Markdown 必须 `marked()` 后再 `DOMPurify.sanitize()` 才 `v-html`
- 点赞状态来自后端 `is_liked`，操作后用响应里的 `likes_count` 覆盖，保证多端一致
- 发帖/编辑共用 `TopicEditView`，靠 `!!route.params.id` 区分；编辑走 `getTopicForEdit`
- `CommentItem` 只冒泡事件，创建评论的请求由详情页统一发起
