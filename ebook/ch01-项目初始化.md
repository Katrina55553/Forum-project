# 第一章：项目初始化 — 搭建骨架

## 技术选型

| 技术 | 用途 |
|------|------|
| **FastAPI** | Python 异步 Web 框架，自动生成 Swagger 文档 |
| **SQLAlchemy** | ORM（对象关系映射），用 Python 类操作数据库 |
| **PostgreSQL** | 数据库（开发时可用 Docker 启动，没有任何 SQLite 回退） |
| **JWT** | 登录后的身份认证令牌 |
| **bcrypt** | 密码加密 |
| **slowapi** | 请求频率限制 |
| **bleach** | HTML 白名单净化，防 XSS |

## 项目目录结构

```
forum-project/
├── docker-compose.yml           # 三服务编排：db / backend / frontend
├── deploy.sh                    # 一键部署脚本（生成 .env、拉代码、构建、seed）
├── .env.example                 # 环境变量模板
├── backend/
│   ├── venv/                    # Python 虚拟环境
│   ├── main.py                  # 入口文件（路由、中间件、错误处理）
│   ├── models.py                # 数据库模型（表结构定义）
│   ├── schemas.py               # 请求/响应数据格式（Pydantic 校验）
│   ├── crud.py                  # 数据库操作函数（纯数据层）
│   ├── auth.py                  # 认证逻辑（密码加密 + JWT 令牌）
│   ├── database.py              # 数据库连接 + 轻量 schema 演进
│   ├── seed.py                  # 测试数据填充脚本
│   ├── requirements.txt         # Python 依赖清单
│   ├── Dockerfile               # 后端容器化配置
│   ├── migrations/              # 历史迁移脚本（一次性档案，见第八章）
│   └── uploads/avatars/         # 用户头像上传目录
└── frontend/                    # Vue 3 前端（ch12 起讲解）
```

后端一共只有 **7 个 Python 文件**，全部代码加起来约 1500 行（实测 1496 行）。这正是 FastAPI 项目的可爱之处：不需要复杂的目录分层，把职责拆到几个文件里就够用。

## 依赖说明（requirements.txt）

每一行对应一个明确的职责：

| 依赖 | 作用 |
|------|------|
| `fastapi>=0.100` | Web 框架本身，处理路由、依赖注入、自动生成 OpenAPI 文档 |
| `uvicorn[standard]` | ASGI 服务器，负责运行 FastAPI 应用 |
| `sqlalchemy>=2.0` | ORM 框架，把 Python 类映射到数据库表 |
| `psycopg2-binary` | PostgreSQL 驱动，让 SQLAlchemy 能连接 PG |
| `bcrypt` | 密码哈希，比 SHA256 更适合存密码（慢 = 安全） |
| `python-jose` | JWT 令牌的生成和验证 |
| `slowapi` | 请求频率限制，防止暴力破解 |
| `bleach` | HTML 内容净化，防止 XSS 跨站脚本攻击 |
| `python-multipart` | 处理表单/文件上传（头像上传依赖它） |

> 注意 `bcrypt` 这一行。项目早期其实用的是 `passlib`，后来因为 passlib 与新版 bcrypt 的版本兼容问题，直接改成调用 `bcrypt` 库本身。教程后续讲 `auth.py` 时你会看到这个选择留下的痕迹。

## 后端文件依赖关系

```
database.py    ← 数据库连接配置（engine、Session、Base、ensure_schema）
     ↓
models.py      ← 表结构定义（继承 database.Base）
     ↓
auth.py        ← 认证逻辑（依赖 models, database）
     ↓
crud.py        ← 数据库操作（依赖 models, auth）
     ↓
main.py        ← 入口文件（依赖所有模块）
     ↓
seed.py        ← 测试数据（依赖 database, models, auth）
```

有一点值得强调：`models.py` 里 `from database import Base`，`crud.py` 里 `from auth import hash_password`——模块之间的依赖是单向的、清晰的，**没有循环引用**。这也是把 `Base` 单独放在 `database.py` 而不是 `models.py` 的原因：让更底层的连接配置不反过来依赖业务模型。

## 环境变量

配置一律外部化，通过环境变量传入（`.env.example` 是模板）：

| 变量 | 默认值 | 作用 |
|------|--------|------|
| `SECRET_KEY` | `dev-only-change-me` | JWT 签名密钥，生产环境必须替换 |
| `CORS_ORIGIN` | `http://localhost:5173` | 允许跨域的前端地址 |
| `DATABASE_URL` | `postgresql://blog:blog@localhost:5432/blog` | 数据库连接串 |
| `DB_PASSWORD` | `change-me` | 仅供 docker-compose 组装数据库密码 |

## 本章要点

1. **职责分离**：每个文件只做一件事，按依赖关系从底层到上层组织（database → models → auth/crud → main）
2. **配置外部化**：数据库地址、密钥、CORS 来源都通过环境变量传入，不硬编码
3. **小即是美**：7 个文件、约 1500 行就是一个完整论坛后端；每个依赖只承担一个明确职责
4. **只认 PostgreSQL**：项目刻意不保留 SQLite 回退路径，避免"开发用 SQLite、上线用 PG"带来的行为差异
