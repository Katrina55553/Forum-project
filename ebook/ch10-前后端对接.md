# 第十章：前后端如何对接

前九章把后端讲完了。这一章回答一个很实际的问题：**前端到底怎么调用这些 API？**（前端的实现细节留给 ch12 之后的章节，这里只讲"对接"这一层。）

## 完整调用链路

```
浏览器
  └─ Vue 组件（HomeView.vue）
       └─ API 函数（api/topic.js）
            └─ Axios 客户端（api/client.js）
                 └─ HTTP → localhost:5173/api/...
                      └─ Vite 代理转发 → localhost:8000/api/...
                           └─ FastAPI 后端 → PostgreSQL
```

## Axios 客户端（api/client.js）

所有请求的公共逻辑都收敛在这一个文件里：

```javascript
import axios from "axios";

const client = axios.create({
  baseURL: "/api",
  timeout: 10000,
});

client.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

client.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      const url = error.config?.url || "";
      // 登录/注册接口的 401 不重定向，让调用方处理错误信息
      const isAuthEndpoint = url.includes("/auth/login") || url.includes("/auth/register");
      if (!isAuthEndpoint) {
        // 清除本地存储
        localStorage.removeItem("token");
        localStorage.removeItem("user");
        // 通知 Pinia store 清除状态
        window.dispatchEvent(new CustomEvent("auth-expired"));
        const currentPath = window.location.pathname;
        if (currentPath !== "/login" && currentPath !== "/register") {
          window.location.href = `/login?redirect=${encodeURIComponent(currentPath)}`;
        } else {
          window.location.href = "/login";
        }
      }
    }
    return Promise.reject(error);
  },
);

export default client;
```

### 自动带 token

从 localStorage 取出之前登录存的 JWT，自动加到 `Authorization` 请求头。所有 API 函数都不用自己处理 token。这正是后端 `HTTPBearer` 期望的格式：`Authorization: Bearer <token>`。

### 401 拦截：这里比"教科书版"多想了三步

拦截器的核心职责是"token 过期了就把用户踢回登录页"，但直接无脑跳转有三个问题，代码里逐一处理了：

1. **登录/注册接口的 401 不该跳转**。用户输错密码时，后端返回的也是 401（第五章：无论用户不存在还是密码错误都返回 401）。如果拦截器无脑跳转，用户在登录页输错密码会被"跳转到登录页"——明明已经在登录页了，页面却刷新了一下、错误提示被清空，体验很糟。所以先判断 `url` 是不是 `/auth/login` 或 `/auth/register`，是就放行给调用方处理
2. **要通知状态管理清状态**。token 失效时，除了删 localStorage，还派发了一个自定义事件 `auth-expired`。Pinia 的用户 store 监听它来清空内存里的用户状态——否则页面顶部可能还显示着"已登录"的头像，点进去却处处 401
3. **登录页/注册页上不要再"跳转到登录页"**。`currentPath !== "/login"` 的判断避免在登录页上自己跳自己，否则可能死循环刷新

### 带 redirect 参数

跳转时带上 `?redirect=${encodeURIComponent(currentPath)}`，登录成功后能跳回用户原本想访问的页面。`encodeURIComponent` 是必须的——页面路径里可能有 `?`、`&`、中文等字符，不编码会破坏 URL 结构。

## API 函数封装

每个后端模块对应一个前端 api 文件，职责一一对应：

```javascript
// api/auth.js
export function register(username, password) {
  return client.post("/auth/register", { username, password });
}
export function login(username, password) {
  return client.post("/auth/login", { username, password });
}
export function getMe() {
  return client.get("/auth/me");
}
export function updateMe(data) {
  return client.put("/auth/me", data);
}
export function changePassword(oldPassword, newPassword) {
  return client.put("/auth/password", { old_password: oldPassword, new_password: newPassword });
}

// api/topic.js
export function getTopics(page = 1, size = 10, q = "", tag = "") {
  return client.get("/topics", { params: { page, size, q, tag } });
}
export function getTopicById(id) { return client.get(`/topics/${id}`); }
export function getTopicForEdit(id) { return client.get(`/topics/${id}/edit`); }
export function createTopic(data) { return client.post("/topics", data); }
export function updateTopic(id, data) { return client.put(`/topics/${id}`, data); }
export function deleteTopic(id) { return client.delete(`/topics/${id}`); }
export function pinTopic(id) { return client.put(`/topics/${id}/pin`); }
export function featureTopic(id) { return client.put(`/topics/${id}/featured`); }

// api/tag.js
export function getTags() { return client.get("/tags"); }

// api/comment.js
export function createComment(topicId, content, parentId = null) {
  return client.post("/comments", { content, topic_id: topicId, parent_id: parentId });
}
export function deleteComment(id) { return client.delete(`/comments/${id}`); }

// api/like.js
export function likeTopic(topicId) { return client.post(`/likes/${topicId}`); }
export function unlikeTopic(topicId) { return client.delete(`/likes/${topicId}`); }

// api/notification.js
export function getNotifications(page = 1, size = 20) {
  return client.get("/notifications", { params: { page, size } });
}
export function getUnreadCount() { return client.get("/notifications/unread-count"); }
export function markRead(id) { return client.put(`/notifications/${id}/read`); }
export function markAllRead() { return client.put("/notifications/read-all"); }

// api/message.js
export function sendMessage(receiver, content) {
  return client.post("/messages", { receiver, content });
}
export function getConversations() { return client.get("/messages"); }
export function getMessages(username, page = 1, size = 50) {
  return client.get(`/messages/${username}`, { params: { page, size } });
}
export function markMessagesRead(username) { return client.put(`/messages/${username}/read`); }
export function getUnreadMessageCount() { return client.get("/messages/unread-count"); }

// api/user.js
export function getUserProfile(username) { return client.get(`/users/${username}`); }

// api/upload.js
export function uploadAvatar(file) {
  const formData = new FormData();
  formData.append("file", file);
  return client.post("/upload/avatar", formData, {
    headers: { "Content-Type": "multipart/form-data" },
  });
}
```

几个值得注意的对应关系：

- **路径不写 `/api` 前缀**，因为 `client.js` 的 `baseURL` 已经加了
- **`getTopics` 的第 4 个参数 `tag`** —— 对应后端 `GET /api/topics` 的 `tag` 查询参数，用来做标签筛选
- **`getTopicForEdit` 与 `getTopicById` 是两个不同接口** —— 前者需要登录并校验"本人或管理员"，只返回 `id/title/content` 三个字段用于回填编辑框；后者是公开的详情，返回完整数据。**编辑页面绝不能直接拿详情数据回填**，否则越权就能读出别人的草稿
- **`pinTopic` / `featureTopic`** —— 前端只负责发请求，权限由后端 `require_admin` 兜住（非管理员会拿到 403）。**前端可以隐藏按钮，但绝不能只靠隐藏按钮做权限**
- **`uploadAvatar` 用 `FormData`** —— 文件上传必须用 `multipart/form-data`，和普通 JSON 请求不一样，所以单独放在 `api/upload.js`

## 视图层 — 三种状态

后端会慢、会失败。每个"拉数据"的视图都必须处理**加载中 / 出错 / 有数据（或空）** 三种状态。以首页为例（`HomeView.vue`）：

```javascript
const topics = ref([]);
const total = ref(0);
const pages = ref(0);
const page = ref(1);
const loading = ref(true);
const error = ref("");

async function fetchTopics() {
  loading.value = true;
  error.value = "";
  try {
    const res = await getTopics(page.value, size, q.value, currentTag.value);
    topics.value = res.data.items;
    total.value = res.data.total;
    pages.value = res.data.pages;
  } catch {
    error.value = "加载失败，请稍后重试";
  } finally {
    loading.value = false;
  }
}

onMounted(() => {
  fetchTopics();
  fetchTags();
});
watch(page, fetchTopics);
```

要点：

- **`finally` 里关掉 loading** —— 无论成功失败都要结束"加载中"，否则出错时骨架屏会一直转
- **`try/catch` 里不写 `e`** —— 前端不需要把后端错误细节暴露给用户，统一给一句"加载失败，请稍后重试"就够了

模板里对应四个分支：

```html
<!-- 加载中：骨架屏 -->
<div v-if="loading" class="skeleton-list">...</div>

<!-- 错误：提示 + 重试 -->
<div v-else-if="error">
  <p>{{ error }}</p>
  <button @click="fetchTopics">重试</button>
</div>

<!-- 空数据 -->
<div v-else-if="topics.length === 0">暂无帖子</div>

<!-- 正常渲染 -->
<div v-else>
  <div v-for="t in topics" :key="t.id">
    <router-link :to="`/topic/${t.id}`">{{ t.title }}</router-link>
  </div>
</div>
```

**空数据和错误必须分开**：`topics.length === 0` 是"请求成功但没有内容"，`error` 是"请求本身失败了"。如果混在一起显示"加载失败"，用户会白白重试一个其实没问题的接口。

### 搜索/筛选用 query 驱动

首页把搜索词和标签筛选都放在 **URL 的 query** 里（`?q=xxx&tag=python`），而不是组件内部状态：

```javascript
function doSearch() {
  const val = searchInput.value.trim();
  page.value = 1;
  const query = {};
  if (val) query.q = val;
  if (currentTag.value) query.tag = currentTag.value;
  router.push({ name: "home", query });
}
```

好处是：用户可以分享链接、可以刷新保持筛选、可以用浏览器后退回到上一次筛选结果。`page.value = 1` 是必须的——换了筛选条件还停在第 5 页，很可能直接看到空列表。

## 完整示例：用户登录

```
用户点击登录
  → auth store: login(username, password)
    → api/auth.js: login(username, password)
      → client.post("/auth/login", {username, password})
        → Vite 代理转发到 :8000
          → 后端验证密码，生成 JWT
        ← 返回 {"access_token": "eyJ...", "token_type": "bearer"}
    ← 拿到 token
    → localStorage.setItem("token", token)
    → restoreUser()
      → client.get("/auth/me")  带着 token
        → 后端 decode JWT → 查数据库
      ← 返回 {id:1, username:"admin", is_admin:true}
  ← 登录完成
  → router.push 跳转到首页
```

## Vite 代理（解决跨域）

```javascript
// vite.config.js
export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      "/api": {
        target: "http://localhost:8000",
        changeOrigin: true,
      },
      "/uploads": {
        target: "http://localhost:8000",
        changeOrigin: true,
      },
    },
  },
});
```

工作流程：

```
浏览器请求 /api/topics
       │
       ▼
  Vite 开发服务器 (:5173)
       │
       ├─ 非 /api → 静态资源
       └─ /api → 转发到 :8000
              │
              ▼
         FastAPI 后端
```

前端写 `baseURL: "/api"` 就够，浏览器只和 5173 通信，**没有跨域问题**——因为浏览器眼里只有同源请求，真正跨域的转发发生在开发服务器内部。

注意 `/uploads` 也配了代理：头像图片的实际地址是 `http://localhost:8000/uploads/avatars/xxx.jpg`，开发时前端 `<img src="/uploads/avatars/xxx.jpg">` 同样需要被转发到后端，否则图片加载不出来。

这套开发时代理和第九章生产环境的 nginx 配置（`/api` 与 `/uploads` 都反代到 backend）**思路完全一致**——所以前端代码在两种环境下不用改一行。

## 前后端数据格式对应

后端列表接口返回格式：

```json
{
  "items": [{...}],   // 数据数组
  "total": 1,          // 总条数
  "page": 1,           // 当前页
  "size": 10,          // 每页条数
  "pages": 1           // 总页数
}
```

前端取值：

- `res.data.items` → 循环渲染列表
- `res.data.total` → "找到 N 篇帖子"
- `res.data.pages` → 生成分页按钮

注意 `res.data` 里的 `items` 每一项已经带好了 `tags`、`is_pinned`、`is_featured` ——列表页要显示的置顶/加精标记、标签，后端都在列表接口里一并返回了，前端不需要为每个帖子再单独请求一次。**"列表接口把列表要用的字段一次给全"，是避免前端 N+1 请求的关键。**

## 本章要点

- 所有请求走统一的 `client.js`：请求拦截器自动带 token，响应拦截器统一处理 401
- 401 拦截要区分"登录接口自己的 401"和"token 过期"，还要派发 `auth-expired` 事件让 Pinia 清状态
- 每个后端模块对应一个 `api/*.js`，路径不带 `/api` 前缀；文件上传单独用 `FormData`
- 编辑回填要用专门的 `/topics/{id}/edit`，不能复用公开详情接口
- 视图必须区分"加载中/出错/空数据"三种状态；筛选条件放 URL query 而非组件内状态
- Vite 开发代理（`/api`、`/uploads`）与生产 nginx 反代思路一致，前端代码无需改动
- 列表接口一次返回列表所需的全部字段（含 tags、置顶标记），避免前端逐条补请求
