# 第十一章：完整开发流程总结

## 后端开发路径

```
Step 1  搭环境      项目结构、虚拟环境、requirements.txt
  │
  ▼
Step 2  数据库      database.py → 连接配置 + ensure_schema
                   models.py → User / Topic / Comment / likes / Notification
                               / Message / Tag / topic_tags（8 张表）
  │
  ▼
Step 3  数据校验    schemas.py → Pydantic 请求/响应模型
  │
  ▼
Step 4  业务逻辑    crud.py → 所有数据库操作函数
  │
  ▼
Step 5  认证系统    auth.py → bcrypt + JWT + 三种依赖
  │
  ▼
Step 6  路由集成    main.py → 29 个 API + 中间件 + 错误处理 + 限流 + 上传
  │
  ▼
Step 7  测试数据    seed.py → 一键填充开发数据（幂等）
  │
  ▼
Step 8  部署        三服务 docker-compose + deploy.sh
```

## 文件依赖关系

```
database.py    ← 数据库连接 + ensure_schema
     ↓
models.py      ← 表结构定义（继承 database.Base）
     │
     ├─── schemas.py  ← 数据校验模型
     │
     ▼
auth.py        ← 认证（依赖 models, database）
     ↓
crud.py        ← 数据库操作（依赖 models, auth）
     │
     ▼
main.py        ← 入口文件（依赖所有模块）
     │
     ▼
seed.py        ← 测试数据（依赖 database, models, auth）
```

## 路由层 vs 数据层

```
        HTTP 请求
            │
            ▼
   ┌────────────────┐
   │   main.py      │  参数解析、速率限制、权限检查、
   │  （路由层）     │  sanitize 过滤、响应格式
   └───────┬────────┘
           │
           ▼
   ┌────────────────┐
   │   crud.py      │  纯数据库读写
   │  （数据层）     │
   └───────┬────────┘
           │
           ▼
   ┌────────────────┐
   │  PostgreSQL    │
   └────────────────┘
```

- ✅ 帖子 CRUD（Markdown 内容、搜索、分页、标签筛选）

- ✅ 评论系统（楼中楼无限嵌套、级联删除子回复）
- ✅ 点赞功能（幂等设计，并发安全）
- ✅ 通知系统（自动触发 + 三重去重规则）

- ✅ 管理员功能（置顶帖子 / 加精帖子）

## 从"能跑"到"能用"：这个项目教了什么

把这 11 章连起来看，会发现真正让项目从"能跑的 demo"变成"能用的产品"的，往往不是新功能，而是这些细节：

- **数据一致性**：计数用 SQL 表达式、减法用 `case` 兜底、评论与通知单事务提交
- **并发与幂等**：点赞靠唯一约束 + 捕获 `IntegrityError`，seed 靠"先查后建"
- **安全分层**：密码 bcrypt、输入 bleach 净化、上传三重校验、权限 404/403 分明、密钥来自环境变量
- **性能有意识**：`joinedload` 治 N+1、计数避开 JOIN 膨胀、索引按查询模式加
- **简洁的取舍**：没有 Alembic、没有 SQLite 回退、没有过度分层——每个决定都能说出理由

- 后端 7 个文件约 1500 行，前端 16 个组件约 4455 行，构成一个完整论坛
