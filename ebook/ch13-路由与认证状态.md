# 第十三章：路由与认证状态

## 路由定义（router/index.js）

**共 12 条路由，全部懒加载**（`component: () => import(...)`）。旧教程写的是"10 条"，且把 `/notifications` 指向了 `NotificationsView`——这两个说法都已经过时。

| 路径 | 名称 | 视图 | 需登录 |
|------|------|------|:-----:|
| `/` | home | HomeView | 否 |
| `/topic/new` | topic-new | TopicEditView | **是** |
| `/topic/:id` | topic-detail | TopicDetailView | 否 |
| `/topic/:id/edit` | topic-edit | TopicEditView | **是** |
| `/notifications` | — | **重定向到 `/messages`**（无组件） | — |
| `/messages` | messages | MessagesView | **是** |
| `/messages/:username` | chat | ChatView | **是** |
| `/login` | login | LoginView | 否 |
| `/register` | register | RegisterView | 否 |
| `/profile/edit` | profile-edit | ProfileEdit | **是** |
| `/user/:username` | user-profile | UserProfile | 否 |
| `/:pathMatch(.*)*` | not-found | NotFoundView | 否 |

```javascript
const routes = [
  { path: "/", name: "home", component: () => import("../views/HomeView.vue"), meta: { title: "首页" } },
  // ...
  {
    path: "/notifications",
    redirect: "/messages",     // 没有 component，直接重定向
  },
  {
    path: "/messages",
    name: "messages",
    component: () => import("../views/MessagesView.vue"),
    meta: { requiresAuth: true, title: "消息" },
  },
  // ...
];
```

### 为什么 `/notifications` 是一条"空路由"

通知和私信在体验上是同一件事——"有人找你"，所以被合并成了一个统一收件箱 `/messages`。但外部可能还有旧链接指向 `/notifications`（书签、历史消息里发出去的链接），于是保留一条**纯重定向**路由兜底：

```javascript
{ path: "/notifications", redirect: "/messages" }
```

它没有 `name`、没有 `component`、没有 `meta`——它唯一的职责就是把老地址平滑地送到新地址。这正是"路由表里一条条目不一定是页面"的典型例子。

## 导航守卫 — 认证拦截

这是旧教程错得最明显的地方：**当前代码用的是 Vue Router 4 的返回值写法，不是回调式的 `next()`**。

```javascript
router.beforeEach((to) => {
  const token = localStorage.getItem("token");
  if (to.meta.requiresAuth && !token) {
    return { name: "login", query: { redirect: to.fullPath } };
  }
});
```

**返回值写法的规则：**

- 返回 `undefined`（什么都不返回）→ 放行
- 返回一个路由位置对象 → 重定向到那里
- 返回 `false` → 取消导航

所以这里不需要 `next`，**也不要**写 `(to, from, next)` 三个参数。守卫直接"返回要去的地方"，比回调式更简洁，也更不容易漏掉 `next()` 造成卡死。

**工作流程：**

```
用户访问 /topic/new（requiresAuth: true）
  → 读 localStorage 有没有 token
  → 没有？→ return { name: "login", query: { redirect: "/topic/new" } }
  → 用户登录成功后跳回 /topic/new
```

`redirect` 参数保证了用户体验——登录完成后直接回到原来想去的页面。注意这里用 `to.fullPath`（含查询串），而不是 `to.path`，这样 `/`首页的搜索参数也能被保留。

## 页面标题

```javascript
router.afterEach((to) => {
  document.title = to.meta.title ? `${to.meta.title} · Inkwell` : "Inkwell";
});
```

每个路由的 `meta.title` 会自动成为页面标题，格式是 **`标题 · Inkwell`**（中间是一个间隔号 `·`，不是旧教程里的 `" - Forum"`）。没有 `title` 的路由（如 `/notifications` 重定向）就退化为品牌名 `Inkwell`。

## 滚动行为

```javascript
scrollBehavior() {
  return { top: 0 };   // 每次切换路由回到顶部
}
```

切换页面自动滚到顶部，避免长列表滚动位置"串台"。

## 认证状态管理（stores/auth.js）

全站只有一个 Pinia store，用 Composition API 风格书写：

```javascript
import { defineStore } from "pinia";
import { ref } from "vue";
import { login as apiLogin, register as apiRegister, getMe } from "../api/auth";

export const useAuthStore = defineStore("auth", () => {
  const user = ref(null);
  const token = ref(localStorage.getItem("token") || "");

  // 保存认证信息到内存 + localStorage
  function setAuth(t, u) {
    token.value = t;
    user.value = u;
    localStorage.setItem("token", t);
    localStorage.setItem("user", JSON.stringify(u));
  }

  // 清除认证信息
  function clearAuth() {
    token.value = "";
    user.value = null;
    localStorage.removeItem("token");
    localStorage.removeItem("user");
  }

  async function register(username, password) {
    const res = await apiRegister(username, password);
    return res.data;
  }

  // 登录：先拿 token，再取完整用户信息
  async function login(username, password) {
    const res = await apiLogin(username, password);
    setAuth(res.data.access_token, { username });   // 先存部分信息
    await restoreUser();                            // 再补全 id、is_admin、avatar...
    return res.data;
  }

  async function restoreUser() {
    if (token.value) {
      try {
        const res = await getMe();
        user.value = res.data;
      } catch {
        clearAuth();              // token 失效 → 退出登录
      }
    }
  }

  function logout() {
    clearAuth();
  }

  return { user, token, setAuth, clearAuth, register, login, restoreUser, logout };
});
```

### 为什么 login 要分两步？

登录接口只返回 `access_token`，不返回完整用户信息。所以拿到 token 后立刻调 `getMe()` 补全 `id`、`is_admin`、`avatar` 等字段：

```javascript
const res = await apiLogin(username, password);
setAuth(res.data.access_token, { username });   // 第一步：token + 临时用户名
await restoreUser();                            // 第二步：调 /api/auth/me 补全
```

这里有一个容易踩的坑：`setAuth` 的第一个参数是 `{ username }`，只是个**占位对象**。真正的用户信息以 `restoreUser()` 写入的为准。所以任何直接读 `auth.user.id` 的逻辑，都必须发生在 `restoreUser()` 之后——否则会读到 `undefined`。

### 页面刷新后如何保持登录？

```javascript
// App.vue onMounted 中
await auth.restoreUser();   // 从 localStorage 的 token 恢复用户
```

`user` 初始为 `null`，但 `token` 从 `localStorage` 恢复。启动时只要 token 还在，`restoreUser()` 就能用 `getMe()` 把用户信息取回来。若 token 过期，`getMe()` 抛错会走 `catch` 分支 `clearAuth()`，完成一次干净的登出。

## HTTP 客户端与拦截器 — api/client.js

路由守卫看守的是"进不进的去某个页面"，而真正给每个请求带上身份、并在 token 失效时兜底的，是 Axios 客户端 `api/client.js`。它只做三件事：建实例、注入 token、处理 401。

```javascript
import axios from "axios";

const client = axios.create({
  baseURL: "/api",     // 所有请求自动加 /api 前缀
  timeout: 10000,      // 10 秒超时
});
```

### 请求拦截器：自动带 token

```javascript
client.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

每个请求出去之前都会被"贴"上一句 `Authorization: Bearer <token>`。所以业务代码里**不需要**手动传 token——登录后一切接口自动带上身份。

### 响应拦截器：401 的统一出口

```javascript
client.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      const url = error.config?.url || "";
      // 登录/注册接口的 401 不重定向，让调用方处理错误信息
      const isAuthEndpoint = url.includes("/auth/login") || url.includes("/auth/register");
      if (!isAuthEndpoint) {
        localStorage.removeItem("token");
        localStorage.removeItem("user");
        window.dispatchEvent(new CustomEvent("auth-expired"));   // 通知 Pinia 清状态
        const currentPath = window.location.pathname;
        if (currentPath !== "/login" && currentPath !== "/register") {
          window.location.href = `/login?redirect=${encodeURIComponent(currentPath)}`;
        } else {
          window.location.href = "/login";
        }
      }
    }
    return Promise.reject(error);
  },
);
```

这里有两个精心处理过的细节：

1. **登录/注册接口的 401 不触发重定向。** 用户输错密码时，`/auth/login` 返回 401。如果拦截器一视同仁地跳转，页面会被刷新，用户根本来不及看到"用户名或密码错误"的提示。所以先用 url 判断是不是这两个端点，是的话交回给调用方处理。
2. **先派发事件、再硬跳。** `window.dispatchEvent(new CustomEvent("auth-expired"))` 让还在内存里的 Pinia store 有机会清空状态、停掉轮询（App.vue 里监听它），随后才用 `window.location.href` 做整页跳转。因为整页跳转会重载 JS，只用 `router.push` 是清不掉内存状态的——这就是为什么要"事件 + 硬跳"两步走。

`redirect` 参数会带上当前路径，登录后能跳回来（与路由守卫用的是同一个约定）。

## 本章要点

- 路由共 **12 条**，其中 `/notifications` 是一条**无组件的重定向**，指向 `/messages`
- 守卫用 Vue Router 4 的**返回值写法**，返回位置对象即重定向，无需 `next()`
- 页面标题格式是 `标题 · Inkwell`；`redirect` 用 `to.fullPath` 以保留查询参数
- `token` 预置来自 `localStorage`，`user` 启动时通过 `restoreUser()` 异步补全
- `login` 两步走：先拿 token、再取完整用户信息；`setAuth` 里的 `{ username }` 只是占位
- `api/client.js` 负责请求带 token 与 401 兜底：登录/注册端点不重定向，其余先派发 `auth-expired` 再硬跳登录页
