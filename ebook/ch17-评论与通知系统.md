# 第十七章：评论与通知系统

本章包含三部分：递归评论组件、统一收件箱（通知 + 私信）、一对一聊天。先说一个**必须澄清的事实**：旧教程整整一节的"通知页面 `NotificationsView.vue`"已经作废——那个文件还在仓库里，但**没有任何路由指向它，也没有任何地方 import 它**，是架构演进留下的死代码。通知功能现在活在统一收件箱 `/messages` 里。下面全部以当前代码为准。

## 递归评论组件 — CommentItem.vue

### 组件设计

CommentItem 通过**递归渲染**实现无限层级的楼中楼：自己的模板里又渲染了自己。

```html
<template>
  <div class="comment-thread" :class="{ nested: depth > 0 }">
    <div class="comment-item">
      <div class="comment-avatar">{{ initials(comment.username) }}</div>
      <div class="comment-main">
        <div class="comment-header">
          <router-link :to="`/user/${comment.username}`" class="comment-author">{{ comment.username }}</router-link>
          <span class="comment-dot">·</span>
          <span class="comment-time">{{ new Date(comment.created_at).toLocaleDateString() }}</span>
        </div>
        <p class="comment-body">{{ comment.content }}</p>

        <div class="comment-actions">
          <button v-if="auth" class="btn-link" @click="showReplyForm = !showReplyForm">回复</button>
          <button v-if="canDelete()" class="btn-link btn-danger" @click="handleDelete">删除</button>
        </div>

        <!-- 内联回复表单 -->
        <div v-if="showReplyForm" class="reply-form">
          <textarea v-model="replyText" placeholder="写下你的回复..." rows="2"></textarea>
          <div class="reply-actions">
            <button class="btn-submit" @click="handleSubmit">提交</button>
            <button class="btn-cancel" @click="showReplyForm = false">取消</button>
          </div>
        </div>
      </div>
    </div>

    <!-- ⭐ 递归渲染子评论 -->
    <template v-if="depth < 10">
      <CommentItem
        v-for="reply in comment.replies"
        :key="reply.id"
        :comment="reply"
        :depth="depth + 1"
        :auth="auth"
        @reply-created="emit('reply-created', $event)"
        @comment-deleted="emit('comment-deleted', $event)"
      />
    </template>
  </div>
</template>
```

### Props 与事件

```javascript
const props = defineProps({
  comment: { type: Object, required: true },
  depth: { type: Number, default: 0 },
  auth: { type: Object, default: null },     // 当前登录用户，未登录为 null
});

const emit = defineEmits(["reply-created", "comment-deleted"]);
```

注意事件名是 **`reply-created` / `comment-deleted`**（旧教程写的 `@reply` / `@deleted` 已不准确）。

### 缩进逻辑与递归深度上限

缩进**不是**用 `depth * 20px` 的行内样式算的，而是靠 CSS 类：只要 `depth > 0`，就加上 `.nested` 类，左边距 44px、并带一条左边框：

```css
.comment-thread.nested {
  margin-left: 44px;
  border-left: 1px solid var(--color-border-light);
  padding-left: 16px;
}
```

```
depth=0  评论1
depth=1    ├── 回复1.1        ← .nested，左移 44px
depth=2    │   └── 回复1.1.1  ← .nested，再左移 44px
depth=1    ├── 回复1.2
```

递归在 `depth < 10` 时停止（`<template v-if="depth < 10">`）。这是个**安全阀**：数据异常导致评论树出现环、或有人刻意刷深楼层时，能保证渲染不会无限递归下去。

### 删除权限

`canDelete` 是一个**函数**（不是 computed），在模板里以 `canDelete()` 调用：

```javascript
function canDelete() {
  if (!props.auth) return false;
  return props.auth.id === props.comment.user_id || props.auth.is_admin;
}
```

规则是"本人或管理员"。因为 `props.auth` 可能为 `null`（未登录），先做空值保护再比较。

### 内联回复：只冒泡，不发请求

点击"回复"展开一个 textarea，**不跳转页面**。提交时组件只把"回复谁的哪条、内容是什么"冒泡给父组件，自己**不调用创建评论的接口**：

```javascript
function handleSubmit() {
  if (!replyText.value.trim()) return;
  emit("reply-created", {
    parentId: props.comment.id,          // 被回复的评论 id → 作为 parent_id
    content: replyText.value,
  });
  replyText.value = "";
  showReplyForm.value = false;
}
```

删除则相反——它自己调用接口，成功后再冒泡"哪条被删了"：

```javascript
async function handleDelete() {
  const ok = await showConfirm("确定删除这条评论吗？");
  if (!ok) return;
  try {
    await deleteComment(props.comment.id);
    showToast.success("评论已删除");
    emit("comment-deleted", props.comment.id);
  } catch (e) {
    showToast.error(e.response?.data?.detail || "删除失败");
  }
}
```

### 数据流

```
TopicDetailView.vue
  ├─ 顶层评论：CommentItem (depth=0)
  │     └─ 子评论：CommentItem (depth=1)
  │           └─ 孙评论：CommentItem (depth=2) ...
  │
  ├─ @reply-created  → handleComment(parentId, content) → createComment → fetchTopic
  └─ @comment-deleted → handleCommentDeleted() → fetchTopic
```

**每条回复都会一路向上冒泡到详情页**，由详情页统一调 `createComment(topicId, content, parentId)`，然后 `fetchTopic()` 重新拉取整棵评论树。这样保证新增的楼层一定出现在正确位置，不用在前端手动往嵌套数组里插数据。

> 补充：回复表单的占位文案是"写下你的回复..."，**没有**"回复 @用户名"这类针对特定人的前缀提示。

## 统一收件箱 — MessagesView.vue

通知和私信在产品上是同一件事——"有人找你"，所以被合并成一个列表。`MessagesView` 在挂载时**并发**拉取通知和会话，再把两种数据归一化成同一种结构。

### 并发拉取 + 归一化

```javascript
import { getConversations } from "../api/message";
import { getNotifications, markRead } from "../api/notification";

async function fetchMessages() {
  loading.value = true;
  error.value = "";
  try {
    // 同时获取通知和私信
    const [notifRes, convRes] = await Promise.all([
      getNotifications(1, 50),
      getConversations(),
    ]);

    const notifications = (notifRes.data.items || []).map(n => ({
      type: "notification",
      id: `notif-${n.id}`,
      sourceId: n.id,
      username: "系统通知",
      avatar: "",
      preview: n.type === "reply" ? "有人回复了你的帖子" : "你有新通知",
      time: n.created_at,
      unread: !n.is_read,
      topicId: n.topic_id,
    }));

    const conversations = (convRes.data || []).map(c => ({
      type: "message",
      id: `msg-${c.username}`,
      username: c.username,
      avatar: c.avatar,
      preview: c.last_message,
      time: c.last_message_at,
      unread: c.unread_count > 0,
      unreadCount: c.unread_count,
    }));

    // 合并并按时间倒序
    messages.value = [...notifications, ...conversations]
      .sort((a, b) => new Date(b.time) - new Date(a.time));
  } catch {
    error.value = "加载失败";
  } finally {
    loading.value = false;
  }
}
```

关键设计是**归一化**：两种来源的字段名不一样（`is_read` vs `unread_count`、`created_at` vs `last_message_at`），先各自映射成统一的 `{ type, username, preview, time, unread, ... }`，之后列表渲染就只认这一种结构。`id` 加前缀（`notif-` / `msg-`）是为了防止两类 id 撞车。用 `Promise.all` 并发拉取，两个请求同时进行，比串行快一半。

### 渲染：一列之内区分系统通知与私信

```html
<div v-for="msg in messages" :key="msg.id"
     class="message-item" :class="{ unread: msg.unread }"
     @click="openMessage(msg)">
  <div class="avatar" :class="{ system: msg.type === 'notification' }">
    <img v-if="msg.avatar" :src="msg.avatar" :alt="msg.username" />
    <span v-else class="avatar-initial">
      {{ msg.type === 'notification' ? '✦' : msg.username[0]?.toUpperCase() }}
    </span>
  </div>
  <div class="info">
    <div class="header">
      <span class="username" :class="{ system: msg.type === 'notification' }">{{ msg.username }}</span>
      <span class="time">{{ formatTime(msg.time) }}</span>
    </div>
    <div class="preview">{{ msg.preview }}</div>
  </div>
  <div v-if="msg.unread" class="badge">
    {{ msg.type === 'message' && msg.unreadCount ? msg.unreadCount : '' }}
  </div>
</div>
```

- **通知**头像位置用品牌符号 `✦`（无头像时），并加 `.system` 类改成主色渐变底，和真人用户一眼区分
- **私信**无头像时用用户名首字母；右侧角标显示未读条数 `unreadCount`
- 未读项加 `.unread` 类，底色变成主色的浅色版

### 点击分派

一个列表里两种数据，点击行为也要分流：

```javascript
async function openMessage(msg) {
  if (msg.type === "notification") {
    if (msg.unread) {
      try { await markRead(msg.sourceId); } catch {}   // 先标记已读
    }
    if (msg.topicId) {
      router.push(`/topic/${msg.topicId}`);            // 通知 → 跳相关帖子
    }
  } else {
    router.push(`/messages/${msg.username}`);          // 私信 → 进聊天
  }
}
```

通知点开后**先标记已读再跳转**；私信则直接进入与对方的聊天页。

## 一对一聊天 — ChatView.vue

`ChatView` 由 `/messages/:username` 进入，用路由参数里的用户名拉取对话。

### 拉取与自动标记已读

```javascript
async function fetchMessages() {
  try {
    const res = await getMessages(route.params.username);
    messages.value = res.data.messages;
    otherUser.value = res.data.other_user;
    await nextTick();
    scrollToBottom();
  } catch (e) {
    if (e.response?.status === 404) {
      error.value = "用户不存在";
    } else {
      error.value = "加载失败";
    }
  } finally {
    loading.value = false;
  }
}
```

`getMessages()` 返回 `{ messages, other_user, total }`。**读取时后端会自动把这些消息标记为已读**，所以前端不必再单独发一个"标记已读"请求（`markMessagesRead` 仅在需要时另行调用）。拉到数据后 `nextTick()` 再滚动到底部，确保等 DOM 更新完再滚。

### 气泡：按发送者区分左右

```html
<div v-for="msg in messages" :key="msg.id"
     class="message" :class="{ mine: msg.sender_id === auth.user?.id }">
  <div class="bubble">{{ msg.content }}</div>
  <div class="time">{{ formatTime(msg.created_at) }}</div>
</div>
```

```css
.message.mine { align-self: flex-end; align-items: flex-end; }
.message.mine .bubble { background: var(--color-primary); color: #fff; }
```

判断依据是 `msg.sender_id === auth.user?.id`：**自己发的靠右、主色底白字；对方发的靠左、浅底描边。** 用 `auth.user?.id` 的可选链做兜底，避免用户信息还没加载完时报错。

### 发送后重新拉取

```javascript
async function handleSend() {
  const content = newMessage.value.trim();
  if (!content || sending.value) return;
  sending.value = true;
  try {
    await sendMessage(route.params.username, content);
    newMessage.value = "";
    await fetchMessages();      // 发送成功后重新拉取，而不是本地追加
  } catch (e) {
    showToast.error(e.response?.data?.detail || "发送失败");
  } finally {
    sending.value = false;
  }
}
```

发送后**重新 `fetchMessages()`** 而不是往数组里 push 一条"临时消息"。好处是不用在前端伪造消息 id 和时间、也自动拿到最新顺序；代价是多一次请求。对聊天这种低频操作，这个取舍是划算的。

### 每 10 秒轮询 + 卸载清理

```javascript
let pollTimer = null;

onMounted(() => {
  fetchMessages();
  pollTimer = setInterval(fetchMessages, 10000);   // 每 10 秒拉一次新消息
});

onUnmounted(() => {
  if (pollTimer) clearInterval(pollTimer);
});
```

聊天页用 10 秒轮询（比 App.vue 未读数的 30 秒更频繁），并在 `onUnmounted` 里清掉定时器——离开页面若不清，定时器会一直请求、白白耗费资源。

### 键盘处理：Enter 发送、Shift+Enter 换行、中文输入法

```javascript
function onKeydown(e) {
  if (e.key === "Enter" && !e.shiftKey && !e.isComposing) {
    e.preventDefault();
    handleSend();
  }
}
```

三个条件缺一不可：

- `e.key === "Enter"`：只处理回车
- `!e.shiftKey`：Shift+Enter 留给"换行"
- **`!e.isComposing`**：这是最容易被忽略的一条。中文/日文等输入法在组字过程中按回车（确认候选词）也会触发 `keydown`。如果不判断 `isComposing`，用户用中文输入法选词时一按回车就会把没写完的消息发出去。加上这个判断，组字期间的回车只用于"上屏候选词"。

### 同组件复用：从一个对话切到另一个

`/messages/A` 和 `/messages/B` 用的是**同一个组件**，路由变化时组件不会重建。所以必须监听路由参数手动重新加载：

```javascript
watch(() => route.params.username, (newName) => {
  if (newName) {
    loading.value = true;
    error.value = "";
    fetchMessages();
  }
});
```

同样的"路由参数变化要重新加载"处理也出现在 `TopicDetailView`（监听 `route.params.id`）、`UserProfile`（监听 `route.params.username`）、`TopicEditView`（监听 `route.params.id`）。这是 Vue Router 同组件复用场景下的通用模式：**只要靠路由参数取数据，就得 watch 这个参数。**

## 前后端对应总结

```
发评论：前端 createComment(topicId, content, parentId)
  → POST /api/comments { content, topic_id, parent_id }
  → 后端创建评论 + 更新用户评论数
  → 后端通知帖子作者（除非自回复）
  → 返回 CommentResponse（详情页随后 fetchTopic 重新拉整棵树）

看消息：前端并发 getNotifications(1, 50) + getConversations()
  → GET /api/notifications、GET /api/messages
  → MessagesView 归一化后合并排序

标记通知已读：markRead(id) → PUT /api/notifications/{id}/read

看某人的聊天：getMessages(username) → GET /api/messages/{username}
  → 返回 { messages, other_user, total }，后端自动标记已读

发私信：sendMessage(receiver, content) → POST /api/messages { receiver, content }
```

## 本章要点

- CommentItem 用递归渲染楼中楼，靠 `.nested` 类缩进 44px，`depth < 10` 是递归安全阀
- 评论事件名为 `reply-created` / `comment-deleted`；组件只冒泡事件，创建请求由详情页统一发起
- `canDelete()` 是函数而非 computed，先判空再比较"本人或管理员"
- `NotificationsView.vue` 是**无路由、无引用的死代码**，通知功能已并入 `/messages` 统一收件箱
- MessagesView 用 `Promise.all` 并发拉取，把通知与会话归一化后合并按时间倒序
- ChatView 靠 `sender_id === auth.user?.id` 分左右气泡，发送后重新拉取，每 10 秒轮询并在卸载时清理
- Enter 发送要判断 `!e.isComposing`，否则中文输入法选词时会误发
- 同组件复用时必须 `watch` 路由参数重新加载数据
