# 第十六章：认证与用户页面

本章覆盖四个页面：登录、注册、用户主页、编辑资料，外加 404。

## 登录 — LoginView.vue

### 表单

登录表单用 `label` 包裹输入框，没有独立的 `.field` 结构：

```html
<form @submit.prevent="handleLogin">
  <div v-if="error" class="error">{{ error }}</div>
  <label>
    <span>用户名</span>
    <input v-model="username" type="text" autocomplete="username" placeholder="输入你的用户名" />
  </label>
  <label>
    <span>密码</span>
    <input v-model="password" type="password" autocomplete="current-password" placeholder="输入你的密码" />
  </label>
  <button type="submit" :disabled="loading">
    {{ loading ? "登录中..." : "登录" }}
  </button>
</form>
```

### 登录逻辑：注意 redirect 的安全校验

```javascript
const router = useRouter();
const route = useRoute();
const auth = useAuthStore();

const username = ref("");
const password = ref("");
const error = ref("");
const loading = ref(false);

async function handleLogin() {
  error.value = "";
  if (!username.value || !password.value) {
    error.value = "请填写用户名和密码";
    return;
  }
  loading.value = true;
  try {
    await auth.login(username.value, password.value);
    const redirect = route.query.redirect;
    const safeRedirect = (typeof redirect === 'string' && redirect.startsWith('/') && !redirect.startsWith('//'))
      ? redirect
      : '/';
    router.push(safeRedirect);
  } catch (e) {
    error.value = e.response?.data?.detail || "登录失败";
  } finally {
    loading.value = false;
  }
}
```

三个细节值得讲：

1. **错误信息来自后端。** 不再是固定的"用户名或密码错误"，而是读 `e.response?.data?.detail`。这样后端返回什么就显示什么（比如"密码错误""账号被禁用"）。这也正是 `api/client.js` 里对 `/auth/login` 的 401 **不重定向**的原因——不然这条错误还没显示页面就跳走了。
2. **`redirect` 做了安全校验。** 只接受以 `/` 开头、且不以 `//` 开头的字符串。`startsWith("//")` 是"协议相对 URL"，攻击者可以用 `//evil.com` 把用户带出站外（开放重定向）。不满足条件的就回落到首页 `/`。
3. **登录后跳转用 `router.push`**，保留 SPA 体验；而 token 失效时 `api/client.js` 用的是 `window.location.href` 硬跳（因为要清空内存状态）。

## 注册 — RegisterView.vue

### 前端校验

```javascript
async function handleRegister() {
  error.value = "";
  if (!username.value || !password.value) {
    error.value = "请填写用户名和密码";
    return;
  }
  if (password.value !== confirm.value) {
    error.value = "两次密码不一致";
    return;
  }
  loading.value = true;
  try {
    await auth.register(username.value, password.value);
    router.push("/login");                    // 注册成功直接去登录页
  } catch (e) {
    error.value = e.response?.data?.detail || "注册失败";
  } finally {
    loading.value = false;
  }
}
```

- 前端只做基本检查（非空、两次密码一致），**不判断"用户名是否已存在"**——那是服务端的职责
- 错误信息同样取自 `e.response?.data?.detail`。用户名重复时后端返回 409，`detail` 里就是"用户名已存在"之类的文案
- 注册成功后**不自动登录**，跳到 `/login` 让用户手动登录，逻辑更简单也更符合直觉

## 用户主页 — UserProfile.vue

### 拉取资料

```javascript
import { getUserProfile } from "../api/user";

const profile = ref(null);
const loading = ref(true);
const error = ref("");

async function fetchProfile() {
  loading.value = true;
  error.value = "";
  try {
    const res = await getUserProfile(route.params.username);
    profile.value = res.data;      // 资料 + topics 一次返回
  } catch {
    error.value = "用户不存在或加载失败";

    loading.value = false;
  }

```

接口 `/users/{username}` 一次返回用户资料和 TA 的帖子列表（`res.data.topics`），所以不需要第二个请求。

### GitHub 链接的 XSS 防护

外链地址来自用户填写，不能直接塞进 `href`（否则可能是 `javascript:` 伪协议）。用一个白名单函数只放行 http/https：

```javascript
function isSafeUrl(url) {
  try {
    const u = new URL(url, window.location.origin);
    return u.protocol === "http:" || u.protocol === "https:";
  } catch {
    return false;
  }
}
```

```html
<a v-if="profile.github_url && isSafeUrl(profile.github_url)"
   :href="profile.github_url" target="_blank" rel="noopener noreferrer" class="github-link">
  GitHub
</a>
```

`target="_blank"` 配 `rel="noopener noreferrer"`，防止被打开的页面通过 `window.opener` 反向操作当前页。

### 发私信按钮

当访问的是别人的主页时，显示一个跳到聊天的按钮：

## 编辑资料 — ProfileEdit.vue

页面里有两个独立表单：资料编辑、密码修改。

### 资料编辑（含头像上传）

资料表单支持**三种**头像设置方式：上传文件、输入图片 URL、保留原头像。核心是"文件先本地预览，提交时才真正上传"：

```javascript
import { updateMe, changePassword } from "../api/auth";
import { uploadAvatar } from "../api/upload";

function handleFileSelect(e) {
  const file = e.target.files[0];
  if (!file) return;
  avatarFile.value = file;
  // 释放上一次的 ObjectURL 避免内存泄漏
  if (avatarPreview.value && avatarPreview.value.startsWith("blob:")) {
    URL.revokeObjectURL(avatarPreview.value);
  }
  avatarPreview.value = URL.createObjectURL(file);   // 本地即时预览
}
```

```javascript
async function handleSave() {
  error.value = "";
  saving.value = true;
  try {
    let avatarUrl = avatar.value;
    // 如果选择了新文件，先上传
    if (avatarFile.value) {
      uploading.value = true;
      const res = await uploadAvatar(avatarFile.value);
      avatarUrl = res.data.url;          // 后端返回的最终 URL
      uploading.value = false;
    }
    const res = await updateMe({
      avatar: avatarUrl || null,
      bio: bio.value || null,
      github_url: githubUrl.value || null,
    });
    auth.user = res.data;                                        // 同步 Pinia
    localStorage.setItem("user", JSON.stringify(res.data));      // 同步 localStorage
    success.value = true;
  } catch (e) {
    uploading.value = false;
    error.value = e.response?.data?.detail || "保存失败";
  } finally {
    saving.value = false;
  }
}
```

#### 为什么要用 `URL.createObjectURL`

用户选了图片后，浏览器还没上传，但要立刻让用户看到效果。`URL.createObjectURL(file)` 把本地文件变成一个 `blob:` 临时地址，赋给 `<img src>` 就能即时预览。**这个地址会占用内存**，所以在每次替换前先 `URL.revokeObjectURL` 释放上一个——这是很容易被忽略、但顺手就能做对的内存管理细节。

#### 上传用的是 multipart

`uploadAvatar` 在 `api/upload.js` 里用 `FormData` 构造 multipart 请求：

```javascript
export function uploadAvatar(file) {
  const formData = new FormData();
  formData.append("file", file);
  return client.post("/upload/avatar", formData, {
    headers: { "Content-Type": "multipart/form-data" },
  });
}
```

提交顺序是**先上传拿到 URL，再连同 bio、github_url 一起 `updateMe`**，避免存下 blob 临时地址这种无效数据。

表单里还留了一个 `<details>` 折叠的"或输入图片 URL"输入框，作为上传之外的备选。

### 密码修改

```javascript
async function handleChangePassword() {
  pwError.value = "";
  if (!oldPassword.value || !newPassword.value) {
    pwError.value = "请填写旧密码和新密码";
    return;
  }
  pwSaving.value = true;
  try {
    await changePassword(oldPassword.value, newPassword.value);
    pwSuccess.value = true;
    oldPassword.value = "";
    newPassword.value = "";
  } catch (e) {
    pwError.value = e.response?.data?.detail || "修改失败";
  } finally {
    pwSaving.value = false;
  }
}
```

注意这个表单**只有"旧密码 + 新密码"两个字段**，没有"确认新密码"（和注册不同）。成功后清空输入并显示成功提示，同时把错误交给后端 `detail`（比如"旧密码错误"）。资料表单和密码表单各自持有独立的 `error / success` 状态，互不干扰。

中间那个 `✦` 用的是品牌符号，把 404 也纳入了整体视觉语言。由兜底路由 `/:pathMatch(.*)*` 承接所有未匹配的地址。

## 本章要点

- 登录成功后用 `route.query.redirect` 回跳，但要校验只为站内路径（拒绝 `//` 开头的协议相对 URL）
- 登录/注册的错误文案统一取自后端 `e.response?.data?.detail`
- 用户主页一次请求拿到资料 + 帖子；外链与头像 URL 都要做安全校验
- 头像上传：`URL.createObjectURL` 做本地预览、替换前 `revokeObjectURL` 释放；提交时先 `uploadAvatar` 再 `updateMe`
- 密码表单只有旧/新两个字段，无确认框；两个表单各自独立维护状态
